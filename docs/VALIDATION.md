# 검증 결과

2026-10-20, 작업 브랜치에서 Python 정적 서버와 로컬 Chromium을 실행해 확인했습니다. GitHub Pages 설정은 `main` 브랜치의 `/` 경로를 사용하며, 설정 변경·병합·배포는 실행하지 않았습니다.

## 통과한 검사

| 검사                   | 실행 / 범위                                                        | 결과                                                                             |
| ---------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 정적 HTTP·문서 구조    | `python3 tools/check_site.py`                                      | 5개 HTML, 33개 고유 내부 HTTP 대상, 앵커·상대 경로·리소스 정상                   |
| GitHub Pages 하위 경로 | 임시 `/portfolio/` 서버로 HTML·CSS·파비콘 요청                     | 루트 도메인에 의존하는 경로 없음                                                 |
| 외부 링크              | `python3 tools/check_site.py --external`                           | GitHub 프로젝트·소스·프로필, INC 공개 사이트, Velog 등 19개 URL 모두 HTTP 200    |
| 반응형                 | Chromium, 너비 320·390·768·1024·1440px × 5개 페이지                | 25개 조합 모두 가로 넘침·실패 요청·JS 페이지 오류 없음                           |
| 접근성 자동 검사       | axe-core 4.10.3, WCAG 2.0/2.1 A·AA 및 best-practice                | 25개 조합에서 위반 0건. 초기 검사에서 발견한 중첩 보충 랜드마크는 수정 후 재검사 |
| 키보드·목차            | 각 화면 조합에서 Tab → 본문 건너뛰기, 프로젝트·회고 목차 링크 클릭 | 본문으로 키보드 포커스 이동. 고정 헤더에 가려지지 않는 목차 목적지 확인          |

| 회고 본문 보존         | 기준 `origin/main`과 `<article>`의 텍스트 비교 (공백 정규화)       | 문장·순서 동일                                                                   |
| 변경 파일 검사         | `git diff --check`                                                 | 공백 오류 없음                                                                   |

브라우저 검사 재실행 명령은 README에 있습니다. 추가로 25개 화면 조합에서 `document.activeElement.id === 'main'`을 확인해 본문 건너뛰기의 포커스 이동을 검증했습니다.

## 수동 화면·대비 확인

데스크톱·모바일 메인 전체 화면과 프로젝트·회고의 실제 렌더링을 열어 정보 위계와 줄바꿈을 확인했습니다. 태블릿에서는 소개 보조 패널이 문장을 좁게 끊는 것을 확인해 1000px 이하에서 숨겼습니다. 모바일 회고의 시간 처리 도식은 줄바꿈된 화살표가 모호하지 않도록 세로 흐름으로 조정하고 320·390px에서 가로 넘침·axe 검사를 다시 통과했습니다.

axe의 `incomplete`는 화살표와 브라우저 도식의 원형 문자에 대한 `color-contrast` 판정이었습니다. 해당 요소의 실제 CSS 전경색과 불투명 배경색으로 대비를 별도 계산했습니다. 장식 원은 **4.89:1**, 도식 화살표는 **6.70:1**, 버튼 화살표는 **9.27:1**입니다. 자동 검사 미판정을 전체 접근성 인증으로 간주하지 않았습니다.

PR 검토용 캡처는 앱 화면이 아닌 **수정한 포트폴리오 사이트의 로컬 렌더링**입니다.

## 확인하지 않은 범위

- 실물 iOS·Android 기기와 Safari·Firefox, 스크린리더 사용자 테스트는 수행하지 않았습니다. Chromium의 실제 렌더링·자동 검사·키보드 검사를 수행했습니다.
- 포레스트링의 현재 설치·스토어 UI, 운영 DB, 실제 수강생 계정이나 INC의 로그인 이후 관리 기능은 실행하지 않았습니다. 해당 설명은 소스·README·사용자 제공 경험을 근거로 합니다.
- 외부 URL의 HTTP 200은 로그인·파일 다운로드·게시물 전체 내용의 정확성을 보증하지 않습니다. 실제 이메일 전송도 수행하지 않았습니다.
- 세 디자인 레퍼런스는 Python HTTPS 요청으로 HTTP 200과 문서 구조를 확인했습니다. 클라우드 Chromium의 외부 HTTPS 인증서 신뢰 문제로 레퍼런스 사이트 자체의 브라우저 캡처는 완료하지 못했습니다. TLS 검증은 끄지 않았습니다. 로컬 포트폴리오 렌더링에는 영향이 없습니다.
- DCC의 공개 저장소는 확인되지 않아 추정 URL과 미확인 모델 세부사항을 넣지 않았습니다.
- 최신 앱 스크린샷을 확보·검증하지 않았습니다. [필요한 화면과 촬영 기준](SCREENSHOTS.md)을 별도로 정리했습니다.
- 새 디자인의 공개 사이트 배포 및 배포 후 검증은 수행하지 않았습니다.
